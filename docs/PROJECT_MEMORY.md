# حافظهٔ محصول زر‌سیگنال

این فایل مرجع پایدار تصمیم‌های محصول و نقاط باز است. تغییر هر مورد باید با دلیل و تاریخ ثبت شود.

## هدف محصول

زر‌سیگنال یک دیده‌بان فارسی برای بازار طلای آب‌شده، نقره و ارز ایران است. ارزش محصول باید در ساده‌سازی تصمیم، زمان و منبع شفاف داده، و مدل تحلیل قابل توضیح باشد؛ نه شلوغ‌کردن صفحه با شاخص‌های بدون زمینه.

## تجربهٔ اصلی

1. کاربر در چند ثانیه نبض بازار و زمان داده را می‌بیند.
2. برای طلا، نقره و دلار وضعیت حباب را پس از آماده‌شدن مدل می‌بیند.
3. جزئیات هر نماد، واحد، خرید، فروش، منبع و تاریخچه را باز می‌کند.
4. در صورت نیاز با ماشین‌حساب شفاف آبشده کار می‌کند.
5. کاربر پریمیوم، هشدار و API را بعد از تکمیل پرداخت و کنترل دسترسی دریافت می‌کند.

## اصول طراحی

- هر کارت یک سؤال را پاسخ می‌دهد؛ از داشبوردهای فشرده و چندرنگ پرهیز شود.
- حرکت صرفاً برای نشان‌دادن تازگی داده و هدایت چشم است؛ با `prefers-reduced-motion` متوقف می‌شود.
- دادهٔ نمایشی، قدیمی یا ناقص هرگز به شکل قیمت زنده یا سیگنال نمایش داده نمی‌شود.
- رنگ سبز و قرمز به‌تنهایی معنی ندارند؛ متن وضعیت کنارشان لازم است.
- طراحی RTL، فونت فارسی خودمیزبان و تعامل لمسی از ابتدا الزامی است.
- تصویر اشتراک‌گذاری شبکه‌های اجتماعی باید پیام و هویت مستقل برند را داشته باشد.

## معماری مورد توافق

- Next.js + TypeScript برای وب و API سرور.
- PostgreSQL + Prisma برای داده، اشتراک، کلید و تاریخچه.
- worker مستقل برای دریافت دوره‌ای قیمت.
- Expo برای اپ iOS و Android با API مشترک.
- لایه‌های `lib`، `server` و `components` جدا نگه داشته می‌شوند؛ صفحه‌ها هماهنگ‌کننده‌اند، نه محل منطق کسب‌وکار.
- محاسبات مالی از `Decimal` در دیتابیس و رشتهٔ اعشاری در API استفاده می‌کنند.

## امنیت و عملیات

- کلید API فقط هش می‌شود؛ secret فقط یک بار به کاربر تحویل داده می‌شود.
- پنل مدیریت با نشست HttpOnly امضاشده و رمز محیطی مستقل محافظت می‌شود.
- پرداخت باید سمت سرور تأیید و idempotent باشد.
- منبع داده تنها با اجازهٔ جمع‌آوری/بازنشر و selectorهای بررسی‌شده فعال می‌شود.

## ابهام‌های باز

- فرمول حباب، اهداف قیمت، افق زمانی و نمونه‌های مرجع
- فرمول و قواعد کسب‌وکار ماشین‌حساب آبشده
- منبع دادهٔ دارای مجوز و قرارداد بازنشر
- ارائه‌دهندهٔ OTP، Google login، WhatsApp و پرداخت
- پلن‌ها، قیمت، سهمیه API و سیاست بازپرداخت
- نقش‌های ادمین و روند تأیید انتشار تحلیل

## تصمیم‌های اجرایی ۲۰۲۶-۰۹-۱۴

- اجرای رابط development نباید به Docker یا در دسترس بودن PostgreSQL وابسته باشد؛ قابلیت‌های داده‌محور در نبود دیتابیس پیام روشن نشان می‌دهند.
- Docker Compose فقط ابزار اختیاری زیرساخت است و در مسیر اجرای روزانهٔ رابط استفاده نمی‌شود.
- تم دارای سه ترجیح System، Light و Dark است؛ System به تغییر زندهٔ تنظیم سیستم‌عامل واکنش می‌دهد.
- ورود Google در نبود credential غیرفعال و توضیح‌دار است. ورود موبایل فقط پس از انتخاب و اتصال ارائه‌دهندهٔ OTP فعال می‌شود.
- نقش‌های پایه ADMIN، USER، HOME_TRADER، PROFESSIONAL_TRADER و API_CUSTOMER در مدل داده ثبت شدند و مدیریت سمت سرور کنترل می‌شود.
- تعرفه و نسخهٔ قیمت فقط از پنل مدیر ساخته می‌شوند؛ seed هیچ قیمت یا دادهٔ بازار واقعی/نمایشی ایجاد نمی‌کند.
- اعداد `demoQuotes` نباید در رابط عمومی شبیه نرخ بازار نمایش داده شوند؛ تا اتصال feed معتبر، UI فقط وضعیت عدم اتصال نشان می‌دهد.
- مسیر feed ترجیحاً API رسمی سمت سرور با کلید رمز‌شده، timestamp تجاری، واحد صریح و قرارداد بازنشر است؛ scraping بدون تأیید مجوز فعال نمی‌شود.

## تصمیمات اجرایی ۲۰۲۶-۰۹-۱۴ — منبع بازار و تجربهٔ داده

- کارفرما دریافت دوره‌ای از صفحهٔ عمومی `https://hamrate.com/` را برای نسخهٔ فعلی تأیید کرد. خزنده فقط HTML عمومی را می‌خواند، هیچ حفاظتی را دور نمی‌زند و حداقل فاصلهٔ دریافت ۱۸۰ ثانیه است.
- منبع، URL، زمان مشاهدهٔ منبع و زمان دریافت زر‌سیگنال برای هر قیمت حفظ می‌شوند. تغییر selector، زمان کهنه، مقدار نامعتبر یا خرید بیشتر از فروش باعث رد کامل batch می‌شود.
- بازارهای فعلی عبارت‌اند از طلای آبشده حواله، اونس نقره، دلار، یورو، درهم، اونس جهانی طلا و `GOLD 1 OZ` دبی. طلای دبی یک بازار مستقل دلاری است و بدون specification به تومان یا طلای داخلی تبدیل نمی‌شود.
- PostgreSQL و Prisma ذخیره‌ساز اصلی production هستند. چون PostgreSQL روی دستگاه توسعه نصب نیست و کارفرما اجرای بدون Docker خواسته است، فقط در development یک ذخیره‌ساز فایل محلی اتمیک برای مشاهده و آزمون feed واقعی فعال می‌شود؛ production حق fallback به فایل ندارد.
- صفحهٔ FAQ مستقل با canonical و ساختار `FAQPage` ایجاد شد و خلاصهٔ مینیمال آن در صفحهٔ اصلی نمایش داده می‌شود.
- ورودی‌های ماشین‌حساب LTR، فقط عددی، دارای حداکثر یک ممیز و برای مبلغ دارای جداکنندهٔ هزارگان هستند.
- تازگی داده برای کاربر به‌صورت زنده (ثانیه/دقیقه پیش) نمایش داده می‌شود و زمان دقیق در tooltip باقی می‌ماند.
- هر بازار URL و محتوای مستقل، منبع، تازگی، واحد، FAQ و structured data دارد؛ هیچ تحلیل مسدودشده‌ای حدس زده نمی‌شود.
- مدیریت تعرفه در development از ذخیرهٔ محلی استفاده می‌کند تا نبود PostgreSQL جریان local را متوقف نکند؛ production همچنان PostgreSQL است.
- برنامهٔ مرحله‌ای درآمد، رشد، SEO و عرضهٔ موبایل در `docs/GROWTH_AND_RELEASE_PLAN.md` ثبت شد.
